A real defect found on the way, in upstream's RoundToInt64, reached by our harvested
guest_extended_math:

  if (!(rounded >= static_cast<TFloat>(INT64_MIN) && rounded < static_cast<TFloat>(INT64_MAX)))

For float and double, (TFloat)INT64_MAX rounds up to 2^63, so the strict < is correct. For 80-bit
long double INT64_MAX is representable exactly, so llroundl(9223372036854775807.0L) failed the
bound, raised FE_INVALID and returned INT64_MIN. The upper bound is now -(TFloat)INT64_MIN, which
is 2^63 exactly in all three types: unchanged for float and double, correct for long double.

Also restored our four-argument sce::Json::MemAllocator::notifyError over upstream's
zero-argument NotImplemented stub -- taking their Export wholesale had downgraded a working
function -- and corrected our Ngs2Geometry null-output assertion, which expected a thrown
std::invalid_argument where Geom.cpp returns SCE_NGS2_ERROR_INVALID_OUT_ADDRESS. Returning the
error code is the right shape for a function whose ABI returns int, so the test moved, not the
implementation.

Submodules: upstream renamed 3rdparty/libusb to 3rdparty/libusb-cmake and hoisted the whole libusb
setup to the root CMakeLists, so libSceUsbd's copy of the five LIBUSB_* cache variables, the
add_subdirectory and the POSITION_INDEPENDENT_CODE line are gone, the stale gitlink is
deregistered, and our mbedtls entry is kept since upstream has none.

Guards paid for themselves. check-dupes-crossfile found four symbols where upstream's new Math.cpp
had implemented what we harvested into ExtendedMath.cpp and NumericHelpers.cpp (asinl, llroundl,
nearbyintl, nearbyint); each was compared before deletion this time, and all four of ours were
