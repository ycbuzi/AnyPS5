The two return different errors for every rejected call (OpenAGC `0x8a6c0002`, `0x8a6c000b`, `0x8a6c0048` and `0x8a6c0049`, sharpemu generic invalid-argument and already-exists errors), so every rejected call throws, including a lookup before registration. - [sceAgcDcbSetWorkloadsActive, sceAgcDcbSetWorkloadComplete and sceAgcDcbSetWorkloadStreamInactive](../../../core/libs/prx/libSceAgc/DcbState/src/Workload.cpp), [sceAgcAcbSetWorkloadsActive, sceAgcAcbSetWorkloadComplete and sceAgcAcbSetWorkloadStreamInactive](../../../core/libs/prx/libSceAgc/Acb/src/Control.cpp) (libSceAgc) and [sceAgcDriverRegisterWorkloadStream](../../../core/libs/prx/libSceAgcDriver/Resource/src/Registration.cpp) (libSceAgcDriver) - the driver call records only the stream id (1 to 31; it returns 0 for any argument and keeps no stream record). Each call writes one `IT_NOP` of the size of the console sequence [OpenAGC](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/agc_workload_packet.c#L18-L104) derives from the driver, not that sequence. Active is 18 dwords: on the console SET_UCONFIG_REG (4 dwords, `0xcc000000 | streamId` and the low mask to 0x342 and 0x343), WRITE_DATA (5 dwords, the high mask to register 0xc343) and SET_WORKLOAD (opcode 0x1e, 9 dwords, a control word, the address of the stream's slot and the mask); here the stream id and the 64-bit mask of the workload ids, as [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/6f0cddd4404ec5203e71fea77e75fc373299ba3f/src/libs/agc.cpp#L2181-L2269) writes the DCB packet. Complete is 12 dwords: on the console SET_UCONFIG_REG (3 dwords, `0xcd000000 | workloadId << 5 | streamId` to 0x342) and SET_WORKLOAD (9 dwords, the slot address and the 64-bit clear mask of the id), with no WRITE_DATA; here the stream id, the workload id and the clear mask, as KytyPS5 writes it. Stream inactive is 9 dwords: on the console SET_UCONFIG_REG (4 dwords, `0xcc000000 | streamId` and 0 to 0x342 and 0x343) and WRITE_DATA (5 dwords, 0 to register 0xc343), with no SET_WORKLOAD and no slot address; here the stream id and seven zero dwords, since KytyPS5 has no inactive call. Registers 0xc342 and 0xc343 are SQ_THREAD_TRACE_USERDATA_2 and _3 at 0x30d08 and 0x30d0c (Mesa [gfx10.json](https://gitlab.freedesktop.org/mesa/mesa/-/blob/fadee2bd99d47742caf7849bae033a4947f0ff77/src/amd/registers/gfx10.json#L8376-8385), [gfx103.json](https://gitlab.freedesktop.org/mesa/mesa/-/blob/fadee2bd99d47742caf7849bae033a4947f0ff77/src/amd/registers/gfx103.json#L7777-7786)), to which RADV writes its thread trace markers two dwords at a time ([radv_sqtt.c](https://gitlab.freedesktop.org/mesa/mesa/-/blob/fadee2bd99d47742caf7849bae033a4947f0ff77/src/amd/vulkan/tools/radv_sqtt.c#L107-151)). They only feed SQ thread traces, which are not emulated, and the AGC driver already drops libSceAgc's predicated tag writes to 0x342 as carrying no register state (`IsTagMarker` in [Pm4.cpp](../../../core/libs/prx/libSceAgcDriver/Execution/src/Pm4.cpp)), so stream inactive has the console's effect apart from the thread trace. The SET_WORKLOAD of active and complete writes the mask to the stream's slot in a 0x200-byte driver table, which OpenAGC carves from the `SceGnmGpuInfo` region at offset 0x3a000 and publishes as the `Sce.Debug:Gnm` process property ([driver_prospero.c](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/driver_prospero.c#L851-L855), [property](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/driver_prospero.c#L925-L940)); it is not title memory. That write is dropped here, and what reads the table is not verified on hardware: OpenAGC keeps its own use of the sequence disabled on firmware 11.60 after its submissions stalled ([driver_prospero.c](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/driver_prospero.c#L1736-L1742)). The ACB calls write the same packets as the DCB ones, unlike the console: [OpenAGC](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/game_compat.c#L2317-L2318) passes a control flag for the ACB that clears header bit 2 of the SET_UCONFIG_REG and WRITE_DATA packets and bit 30 of the SET_WORKLOAD control word ([test](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/tests/test_workload_packet.c#L48-L62)), and the `IT_NOP` form carries neither. The AGC driver accepts and skips these `IT_NOP`s on graphics and compute queues only when they are not predicated: `Pm4::Validate` throws on a NOP with the predicate bit (header bit 0) set, so a workload packet that `sceAgcSetRangePredication` or `sceAgcSetPacketPredication` predicates throws at submission, as every other `IT_NOP` libSceAgc writes does. All six return null without writing for a null command buffer and for an unregistered or out-of-range stream; complete also for a workload id above 63, and active also for a null workload id array, a count of 0 or above 63, an id above 63 or a duplicate id. The active calls check the stream before they read the workload ids, as OpenAGC does: the console returned null for stream 1 with the ids at address 2 ([measured](https://github.com/mattias800/prosper/blob/df074498e56c0df22d74f9c6622e4709bc1c9a19/prosper/tests/data/console_oracle/agcbuild.golden.tsv#L203)) without faulting. The console oracle in prosper measured only that null return, with no stream registered, three argument patterns each and nothing written ([ACB](https://github.com/mattias800/prosper/blob/df074498e56c0df22d74f9c6622e4709bc1c9a19/prosper/tests/data/console_oracle/agcbuild.golden.tsv#L48-L56), [DCB](https://github.com/mattias800/prosper/blob/df074498e56c0df22d74f9c6622e4709bc1c9a19/prosper/tests/data/console_oracle/agcbuild.golden.tsv#L196-L204)); the packet a registered stream gets is not measured. The `(buf, streamId)`, `(buf, streamId, workloadId)` and `(buf, streamId, workloadIds, workloadCount)` signatures are those of the DCB calls in [OpenAGC](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/game_compat.c#L2317-L2384); no ACB declaration was found. The error codes the console driver returns for an invalid or repeated registration are unknown, so registration never fails here. PPSA29866 calls sceAgcDcbSetWorkloadsActive while building its command buffers (sceAgcDcbSetWorkloadComplete was not observed); nothing else was observed.
- [sceAgcCreatePrimState](../../../core/libs/prx/libSceAgc/Shader/src/PrimState.cpp) (libSceAgc) - the `ge_user_vgpr_en` special is passed to the user configuration registers at whatever offset the shader header stores, as the SPRX does according to [OpenAGC](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/game_compat.c#L1181-L1252), which copies all four specials verbatim (KytyPS5 stops on any other offset). PPSA99039, PPSA99505, PPSA99515 and PPSA99997 build their headers by hand with it at 0x25c (`GE_USER_VGPR1`) instead of 0x262 (`GE_USER_VGPR_EN`), value 0, and run on the console; it is not moved to 0x262, and the driver reads neither register. `ge_cntl`, `vgt_shader_stages_en` and a used `vgt_gs_out_prim_type` must still be at their own offsets, since the driver reads those registers there, so a header that stores one elsewhere throws naming the offset, although by OpenAGC the SPRX would copy it as well
- [sceAgcDcbEventWrite](../../../core/libs/prx/libSceAgc/DcbFlow/src/Sync.cpp) (libSceAgc) - non-sample-dump event types (any event other than 0x38 and 0x39) emit a 2-dword PM4 packet 0x46 without address dwords; the address argument is ignored for these events.
