# libSceHmd2 technical debt

### Silent stubs

- [libSceHmd2](../../../core/libs/prx/libSceHmd2/Export.cpp) has no PS VR2 runtime: `sceHmd2Initialize` returns libSceHmd's `UNSUPPORTED_FEATURE` (0x81110016) for any param, so the other calls answer as before initialization and `sceHmd2Open` returns `NotInitialized` (0x8a720002). These results are restored from the behaviour before #7323 and are not measured on hardware: firmware 13.20's libSceHmd2, with the `/dev/hmd2_cmd` state measured on a retail PS5 with no headset connected (connected flag 0, status 2, user -1), initializes, returns a handle from `sceHmd2Open` and reports `NotDetected`, which the code past the initialization check models but no title reaches. PPSA01317 passes a pointer to 16 zeroed bytes, only tests the result for non-zero and then skips its VR set-up; with initialization succeeding it stopped on `sceHmd2ReprojectionQueryBufferSizeAlign` (#6350). `sceHmd2ReprojectionQueryDisplayBufferSizeAlign` and `sceHmd2ReprojectionQuerySeeThroughBufferSizeAlign` stay unimplemented and throw pending console measurements of their sizes and alignments. The other reprojection and gaze exports throw, and [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) never initializes
- the [libSceHmd2 reprojection session](../../../core/libs/prx/libSceHmd2/Export.cpp) follows [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libHmd2.cpp)'s state machine with the layouts its static_asserts pin: `sceHmd2ReprojectionQueryBufferSizeAlign` answers the 0x100828-byte, 0x100-aligned requirement a retail PS5's firmware 13.60 reports for every argument while the process's positional setting is unset (measured in this pull request's discussion; KytyPS5's 16-byte state is not what the console answers) and, after `sceHmd2ReprojectionSetAllowPositionalReprojection` records a first argument of n = 1 to 5, the 0x1103000 + n * 0x1000000-byte, 0x1000-aligned requirement a retail PS5's firmware 13.40 answers instead, `sceHmd2ReprojectionSetAllowPositionalReprojection` answering 0 for a first argument of 0 to 5, recording it process-wide without an initialization and answering `PARAMETER_INVALID` (0x8A720009) for 6, 7, 8, 0xFF and 0xFFFFFFFF with the previous setting kept, the setting call's second and third parameters and the query's own arguments never changing the answer (measured on a retail PS5's firmware 13.40 in this pull request's discussion, where PPSA23479 and PPSA05666 set 2 before their query and PPSA01317 leaves the setting unset), and the 16-byte, 8-aligned state (output mode, timing in microseconds) the session keeps occupies the start of the 0x100828 buffer, `sceHmd2ReprojectionInitialize` answers `PARAMETER_NULL` (0x8A720008) for a null param or buffer, throws for a see-through buffer (the host has no camera), writes the state into the guest's work buffer with the timing the param carries or the 3000 us default and answers 0, and a second initialization answers `REPROJECTION_ALREADY_INITIALIZED` (0x8A72000C). There is no reprojection stage on the host, so the session is bookkeeping only. `sceHmd2ReprojectionSetTiming` answers reprojection `NOT_INITIALIZED` (0x8A72000B) without a session, throws below 2000 us and above 7000 us (KytyPS5 aborts there, which is not portable) and otherwise records the value rounded up to the next hundred microseconds in the work buffer. `sceHmd2ReprojectionEnableVrMode` answers reprojection `NOT_INITIALIZED` without a session, `VIDEO_OUT_ERROR_INVALID_VALUE` (0x80290001) for an output mode other than KytyPS5's 89/91 Hz (0x2000C) and 119/88 Hz (0x2000F), and otherwise `VIDEO_OUT_ERROR_NO_DEVICE` (0x80290018, [KytyPS5 errno.h](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/errno.h)): the console reports no VR runtime, so the state's output mode stays 0. `sceHmd2ReprojectionTerminate` ends the session: it clears the record under the reprojection mutex and answers 0, so afterwards the gated exports answer `NOT_INITIALIZED` again and a new initialization is accepted; this teardown follows the session model, it is not a console measurement, and the positional setting survives it, as it survives a second initialization. The record is a borrow of the guest's work buffer: the guest keeps the buffer for the session's lifetime and frees it after terminating, every read and write of the record happens inside an export call under the mutex, and no export frees guest memory. A guest that frees the buffer while the session is live breaks that contract, and the writes still land in the guest address space at the address the guest gave, where the guest's own allocator owns the memory again, so the guest corrupts its own heap exactly as it would on hardware
