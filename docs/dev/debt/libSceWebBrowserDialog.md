# libSceWebBrowserDialog technical debt

### Silent stubs

- [libSceWebBrowserDialog](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) - `sceWebBrowserDialogOpen` and `sceWebBrowserDialogOpenForPredeterminedContent` run the common-dialog state machine without displaying an interactive browser, and `sceWebBrowserDialogGetResult` reports that the user cancelled. Minecraft Bedrock (PPSA17221) imports `sceWebBrowserDialogOpenForPredeterminedContent` (#5744). The real export takes a second argument, the allow-list of up to twenty addresses (SharpProspero `docs/dialogs.md`); it is not read here, so no address filtering is modelled, and the exact validation order and codes with a null second argument are unverified. Cookies set with `sceWebBrowserDialogSetCookie` are kept until `sceWebBrowserDialogResetCookie`, but no page is loaded, so they are never sent.

### Unknown function info

- [sceWebBrowserDialogSetCookie, sceWebBrowserDialogResetCookie](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) (libSceWebBrowserDialog) - the signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Dialog/WebBrowserDialog.cs) and the PS4 prototypes in [orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json), which agree. The 280-byte cookie param (size, url, cookie, 256 reserved bytes) and the 2048- and 4096-byte url and cookie buffers also appear in the [ps5debug headers](https://github.com/someguythatmods/PS5Debug-CleanELF/blob/master/Vanilla/include/imports.h); the 264-byte reset param (size, 256 reserved bytes) is SharpProspero's only. No reference gives the error codes: before `sceWebBrowserDialogInitialize` the calls return `NOT_INITIALIZED` and a null param returns `ARG_NULL`, as the other calls do, which is not confirmed for the cookie calls; a param whose size does not match, a null url or cookie and a string that does not end within its buffer throw
